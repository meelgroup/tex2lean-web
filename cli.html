Get started with the CLI

Turn a result from your paper into Lean 4 from a terminal. Tex2Lean prepares the statement and develops proofs checked by Lean. You can review the statement first or enable autonomous mode.

Before you begin

You need Git, your paper’s LaTeX sources, internet access, and several gigabytes for Lean and its libraries. Tex2Lean sets up Lean. Use a signed-in Claude Code or Codex CLI, or a supported API provider. OpenRouter supports proof agents without a separate coding CLI.

Install

With Node.js 22.14 or newer:

npm install -g tex2lean

Or use a standalone installer with its own runtime. On macOS or Linux:

curl -fsSL \
https://raw.githubusercontent.com/meelgroup/tex2lean-releases/main/install.sh \
| sh

On Windows, in PowerShell:

irm `
https://raw.githubusercontent.com/meelgroup/tex2lean-releases/main/install.ps1 `
| iex

The installers verify the release checksum. On macOS and Linux, ensure ~/.local/bin is on your PATH. Manual downloads are also available.

tex2lean --version
tex2lean --help

Formalize your first result

cd /path/to/your/paper
tex2lean connect
tex2lean setup
tex2lean scan
tex2lean targets
tex2lean formalize t1

Check the root paper selected during scanning. Replace t1 with an identifier shown by your scan. formalize without an identifier offers a result picker. It prepares the statement, asks for review when required, then proves. You do not need separate planning and proving commands.

Compare the generated model, algorithm, hypotheses, quantifiers, and theorem with your paper before approving the statement. Follow the review prompt to continue, or request a correction.

tex2lean all offers to work through outstanding results in dependency order. It skips planning review after confirmation. plan remains an alias for formalize; prove works on an existing plan.

Run autonomously

Enable autonomy for one invocation:

tex2lean formalize t1 --autonomous

Or save the preference for this project, shared with VS Code:

tex2lean autonomy on
tex2lean autonomy status
tex2lean formalize t1
tex2lean autonomy off

Autonomy uses declared answers to routine run questions, including statement review. Author decisions, such as major statement changes, can still stop the run. It does not authorize publishing. Choose your model, paper root, and requested result beforehand.

--yes takes the first offered action where permitted; it differs from autonomy’s declared answers. --autonomous locks autonomy on for that invocation.

Pause, resume, and check

Press p to pause, or Ctrl+C to stop. Saved work stays on disk. Resume with the result’s identifier:

tex2lean resume t1
tex2lean check
tex2lean proved t1
tex2lean handoff

check inspects the build and proof obligations; proved inspects a theorem’s assumptions; handoff compares the Lean development with the paper. A successful build alone does not establish semantic correctness.

CLI and VS Code share project state. Pause the active run before switching front ends; only one run can own the project at a time.

Interactive commands and configuration

At tex2lean>, use /formalize t1, /autonomy on, /autonomy off, /autonomy status, /help, /log, or /quit. Text without a slash becomes a note for the run.

Use --project DIR for another paper folder, --agents N for worker concurrency, and --provider NAME to select a model connection. tex2lean --help lists supported providers and options.

Update npm installs with npm install -g tex2lean@latest. For standalone installs, use tex2lean upgrade.
